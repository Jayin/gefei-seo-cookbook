# 贡献指南

感谢你对 Google SEO 实战教程项目的关注！我们欢迎任何形式的贡献。

## 如何贡献

### 1. 报告问题

如果你发现了错误或有改进建议，请：

1. 点击 "Issues" 标签
2. 点击 "New issue" 按钮
3. 填写问题标题和描述
4. 提交问题

### 2. 提交内容

如果你想添加或修改内容，请：

1. Fork 项目
2. 创建你的特性分支 (`git checkout -b feature/AmazingFeature`)
3. 提交你的更改 (`git commit -m 'Add some AmazingFeature'`)
4. 推送到分支 (`git push origin feature/AmazingFeature`)
5. 打开一个 Pull Request

### 3. 内容规范

#### 文件命名

- 使用小写字母
- 使用连字符分隔单词
- 使用 `.md` 扩展名
- 例如：`keyword-research.md`

#### 内容结构

```markdown
# 标题

简介段落

## 二级标题

内容段落

### 三级标题

内容段落

::: tip 提示
提示内容
:::

::: warning 注意
注意事项
:::
```

#### 写作风格

- 使用简洁明了的语言
- 避免使用专业术语，或提供解释
- 使用列表和表格提高可读性
- 添加代码示例说明技术内容
- 使用提示框强调重要信息

#### 代码示例

使用代码块展示代码示例：

```html
<!DOCTYPE html>
<html>
<head>
  <title>页面标题</title>
</head>
<body>
  <h1>标题</h1>
</body>
</html>
```

#### 链接

- 使用相对链接指向其他文档
- 使用绝对链接指向外部资源
- 确保链接有效

```markdown
[链接文字](./other-page.md)
[外部链接](https://example.com)
```

### 4. 图片规范

- 使用 PNG 或 SVG 格式
- 压缩图片大小
- 添加有意义的文件名
- 提供 Alt 属性

```markdown
![图片描述](./images/image-name.png)
```

### 5. 提交规范

#### 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

#### 类型

- `feat`: 新功能
- `fix`: 修复错误
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 代码重构
- `test`: 测试相关
- `chore`: 构建过程或辅助工具的变动

#### 示例

```
docs(guide): 添加关键词研究章节

- 添加关键词研究基础内容
- 添加关键词研究工具介绍
- 添加关键词研究技巧

Closes #123
```

## 开发指南

### 1. 环境准备

确保你已安装：

- Node.js >= 16
- npm >= 7

### 2. 安装依赖

```bash
npm install
```

### 3. 启动开发服务器

```bash
npm run dev
```

访问 http://localhost:5173 查看效果。

### 4. 构建生产版本

```bash
npm run build
```

### 5. 预览生产版本

```bash
npm run preview
```

## 常见问题

### Q: 我可以添加自己的网站作为案例吗？

A: 可以，但需要确保案例有学习价值，并且不违反任何法律法规。

### Q: 我可以修改现有内容吗？

A: 可以，但需要确保修改后的内容质量更高，或者修复了错误。

### Q: 我需要签署 CLA 吗？

A: 目前不需要，但未来可能会要求。

### Q: 我的贡献会被认可吗？

A: 是的，所有贡献者都会被记录在项目中。
